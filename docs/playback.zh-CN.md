# 播放与解码支持

[English](playback.md) | 简体中文

本文说明 Lumy Player 什么时候直接播放、什么时候让服务器转码，以及 HDR、杜比视界和音频的支持情况。

各服务器的功能与输出差异见[服务器功能支持对照](server-support.zh-CN.md)。格式矩阵、匿名真机性能数据和验证边界见[格式兼容性与播放性能参考](playback-compatibility-performance.zh-CN.md)。

## 基本原则

能直接播放就直接播放：画质无损，服务器不需要做额外工作，字幕和音轨都在本机处理。只有本机确实处理不了，或主动限制画质时，才让服务器转码。

- **视频优先硬解。** “设置 → 兼容性 → 允许视频软解”默认关闭。开启后，H.264（包括 High10）和 RV40 的 SDR 视频在硬解不可用或失败时，可以尝试本地软解。要求最长边不超过 1920、短边不超过 1080；分辨率未知、HDR 和更大的视频不进入软解。这个范围只是保护上限，实际流畅度仍取决于设备性能、编码和帧率。软解处理原始视频，不需要服务端转码。
- **RM/RMVB 在本机解封装。** RV40 优先使用设备解码器，不可用时可走上述软解路径；Cook 音频使用 FFmpeg，不受视频软解开关影响。
- **音频先用系统解码器，系统不支持的格式（DTS、DTS-HD、TrueHD 等）由内置的 FFmpeg 解码。** 所以音频很少需要转码。

## 什么时候转码

需要在设置里打开“允许服务器转码”（默认开启）。关闭后始终直接播放；设备播放不了时会报错，并显示原因。

### 起播前就决定转码

下表中的“只换封装”和“只转音频”要求服务端允许复制原视频流；飞牛当前仍会重新编码视频。

| 原因 | 服务器怎么处理 |
|---|---|
| 画质选了限制码率的档位（1080p 20/12 Mbps、720p、480p） | 重新编码视频 |
| 封装格式不支持（支持 MKV、MP4、MOV、WebM、TS、FLV、AVI、OGG、RM/RMVB 等） | 只换封装，视频原样复制，服务器负担很小 |
| 不认识的视频编码（支持 H.264、HEVC、VP9、VP8、AV1、MPEG-2、MPEG-4、VC-1、RV40） | 重新编码 |
| 硬解和已允许且符合条件的软解都不能处理该编码 | 重新编码 |
| 分辨率或帧率超出硬件解码器能力 | 重新编码，超过 1080p 的降到 1080p |
| 10bit 视频没有可用的本地解码路径（符合条件的 H.264 Hi10P 可开启软解） | 重新编码，超过 1080p 的降到 1080p |
| 音频编码设备和 FFmpeg 都不支持 | 只转音频 |
| HDR 片源，但设置里关闭了“电视支持 HDR” | 转成 SDR，降到 1080p |
| 字幕本机显示不了，且开启了“允许服务器烧录字幕”（默认关闭） | 重新编码并烧录字幕 |

### 播放过程中自动改用转码

以下两种情况会从当前位置改用转码继续播放，每次起播最多切换一次：

- **直接播放出错**：
  - 如果是视频解码失败（设备声称支持但实际解不了），重新编码视频。
  - 如果是封装或解析问题，在支持视频流复制的适配中只换封装；飞牛仍重新编码。
- **文件不能跳转**（比如没有索引的 MKV）：续播或快进时，改由服务器从目标位置开始。

网络错误不会触发转码，播放器会先重连重试。

### 转码输出

- **Plex**：使用 HLS + TS，声明支持 H.264 / HEVC 视频及 AAC / AC3 / EAC3 / MP3 音频；转 SDR 时只声明 H.264。AC3 请求上限为 5.1，EAC3 为 7.1，实际输出由服务端决定。当前 HLS 配置不声明 DTS / TrueHD / FLAC / Opus，原片使用这些音频时可能需要服务端转换。
- **Jellyfin / Emby**：普通转码使用 HLS + TS；保留所选内封字幕时使用从起播点生成的 MKV 渐进流，字幕原样带出并由本机渲染，跳转时重建播放流。HLS 请求允许 AAC / AC3 / EAC3 / MP3 / Opus / FLAC，MKV 路径在本机能解码时可追加原音频编码。允许复制不保证服务端实际复制，也不代表所有服务端封装组合都已实播验证。
- **飞牛影视**：使用原生 H.264 HLS 转码；本机能解码时保留 AAC / AC3 / EAC3，其他音频转 AAC，当前输出双声道或 5.1。视频流复制和 7.1 输出尚未接入。
- **字幕处理按输出路径区分**：
  - HLS 未携带的内封轨道不能由本机凭空显示。Plex 内封字幕需要外挂或烧录；Jellyfin/Emby 可以使用上述 MKV 路径保留所选内封字幕。
  - 飞牛原生 HLS 可携带所选文本字幕，也可能按播放计划烧录；图形字幕使用烧录，不提供通用 MKV 字幕保留路径。
  - 外挂字幕在播放源提供相应轨道时由本机显示。字幕必须烧录时，需要允许烧录，或视频已经需要重新编码。

## HDR

- **片源识别**：
  - Plex：识别 HDR10、HLG、杜比视界。HDR10+ 会当作 HDR10。
  - Jellyfin / Emby：识别 HDR10、HDR10+、HLG、杜比视界。
  - 飞牛影视：通过原生轨道元数据识别 HDR10、HDR10+、HLG、杜比视界；实测范围见服务器功能对照。
- **是否输出 HDR 以设置里的“电视支持 HDR”为准**，默认开启。系统检测结果不可靠（不少盒子总是报告支持，或者什么都不报告），只在“播放信息”里作为参考显示。
- **开启时**：HDR 片源直接播放，由盒子和电视处理 HDR 信号。
- **关闭时**：所有 HDR 片源（包括 HLG 和杜比视界）都由服务器转成 1080p SDR H.264，避免在不支持 HDR 的电视上画面发灰。前提是服务器上开启了 HDR 色调映射，否则颜色仍然不对。
- 播放器本身不做色调映射。

## 杜比视界

| Profile | 设备有杜比视界解码器 | 设备没有杜比视界解码器 |
|---|---|---|
| **5**（没有 HDR10 兼容层） | 优先原生播放，失败后尝试 HEVC 兼容路径 | 尝试 HEVC 兼容播放，但颜色可能错误 |
| **8**（8.1 / 8.4） | 使用可用解码器播放 | 用 HEVC 解码器播放 HDR10 / HLG 兼容基础层，随变体而定 |
| **7**（UHD 蓝光双层） | 优先原生播放；解码器卡住时尝试 HEVC 基础层 | 用 HEVC 解码器播放 HDR10 基础层 |

**杜比视界解码器卡住时**：有些盒子会报告支持却不出画面。等待至少 8 秒且已有 5 秒缓冲仍没有首帧时，播放器尝试 HEVC 兼容回退；未达到缓冲条件时最多等待 30 秒。失败的 profile 会记在本机，后续可直接使用兼容路径。P5 视频初始化或解码失败也可触发这条回退。

P7 / P8 兼容基础层播放不等于原生 DV 或增强层完整还原。**P5 没有 HDR10 兼容层**，HEVC 兼容播放仅用于出画面，不执行色彩还原或色调映射，仍可能偏绿、偏粉。正确的原生 DV 输出需要解码器、盒子、显示端及输出链支持对应 profile。

上表不会覆盖“电视支持 HDR”设置的转码策略；关闭该设置并允许服务器转码时，仍会请求转换为 SDR。

## 快进与快退

在 **设置 → 播放 → 快进时长 / 快退时长** 分别选择 5、10、15、30、60 或 120 秒，默认快进 30 秒、快退 10 秒。遥控器快进 / 快退键、控制栏隐藏时的左右键，以及进度条单次调整都会使用设置值；在进度条上长按方向键仍会加速。

## 音频

- **设置 → 音频 → 记住手动音轨选择** 默认开启，控制本机文件音轨和剧集语言记忆。关闭后不读取、不更新记录，重新开启可继续使用。“清除音轨记忆”只清除音轨记录，保留字幕记忆和开关状态。

- **默认关闭直通。** 所有音频解码成 PCM，多声道会下混成立体声：中置和环绕声道按 -3dB 混入左右声道，LFE 丢弃。这样可以倍速播放，也兼容投影仪和电视自带的喇叭。代价是杜比全景声（Atmos）信息会丢失。
- **开启“音频直通”**（接功放时使用）：AC3、EAC3（包括全景声 EAC3-JOC）、DTS、TrueHD 等以原始码流交给功放解码。能直通哪些格式，取决于系统报告的 HDMI 能力。直通的音轨不能倍速，会固定 1x 播放。

## 字幕

- **设置 → 字幕 → 记住手动字幕选择** 默认开启，独立控制主字幕记忆（含关闭字幕）。关闭后不读取、不更新记录，已有记录保留。“清除字幕记忆”只清除字幕记录，保留音轨记忆和开关状态。开启记忆时，两类轨道分别按文件记忆、剧集记忆、语言偏好、服务器选择的顺序匹配。

- 在 **更多 → 副字幕** 中选择第二条字幕。普通文本副字幕排在主字幕下方，默认字号为主字幕的 85%。选中 SRT / WebVTT 副字幕后，可在 **更多 → 副字幕样式** 调整字号、文字颜色和背景，即时生效并记住偏好。ASS / SSA 和图形字幕保留原始样式与位置，原有排版可能重叠，暂不提供样式调整。两条字幕共用字幕延迟设置。副字幕选择只对当前视频 / 版本生效，切换后重置。
- 副字幕必须存在于当前播放源中。转码输出没有携带的内封轨道，不能选作副字幕。
- 直接播放时：
  - SRT、ASS / SSA、WebVTT、PGS、VobSub、DVB 字幕都由本机渲染。
  - ASS / SSA 用 libass 渲染，保留字体、位置和特效。
  - 外挂 SUP / PGS 有独立的本地解析与跳转状态预热路径。MKV 内封 PGS 使用压缩快照和异步渲染，避免在视频加载线程上进行 PNG 编解码。
- 转码时的规则见上文“转码输出”。

## 排查

- 播放时在菜单里打开“播放信息”，可以看到播放方式、转码原因、视频和音频解码器、是否直通，以及 HDR 状态。
- debug 包会把起播决策写进日志（`plan ... -> 播放方式 reasons=...`），用 `adb logcat -s LumyPlayer` 查看。关闭了 logcat 的设备（如极米）上，debug 包还会把日志写到文件里：

  ```bash
  adb shell run-as com.hesier.lumy.debug cat files/debug.log
  ```
