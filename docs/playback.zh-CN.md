# 播放与解码支持

[English](playback.md) | 简体中文

本文说明 Lumy Player 什么时候直接播放、什么时候让服务器转码，以及 HDR、杜比视界和音频的支持情况。

## 基本原则

能直接播放就直接播放：画质无损，服务器不需要做额外工作，字幕和音轨都在本机处理。只有本机确实处理不了时，才让服务器转码成 HLS。

- **视频只用硬件解码。** 不用 FFmpeg 软解视频，因为电视盒子软解 4K 会卡得无法观看。硬解不了的视频交给服务器转码。
- **音频先用系统解码器，系统不支持的格式（DTS、DTS-HD、TrueHD 等）由内置的 FFmpeg 解码。** 所以音频很少需要转码。

## 什么时候转码

需要在设置里打开“允许服务器转码”（默认开启）。关闭后始终直接播放；设备播放不了时会报错，并显示原因。

### 起播前就决定转码

| 原因 | 服务器怎么处理 |
|---|---|
| 画质选了限制码率的档位（1080p 20/12 Mbps、720p、480p） | 重新编码视频 |
| 封装格式不支持（支持 MKV、MP4、MOV、WebM、TS、FLV、AVI、OGG 等） | 只换封装，视频原样复制，服务器负担很小 |
| 不认识的视频编码（支持 H.264、HEVC、VP9、VP8、AV1、MPEG-2、MPEG-4、VC-1） | 重新编码 |
| 设备没有对应的硬件解码器 | 重新编码 |
| 分辨率或帧率超出硬件解码器能力 | 重新编码，超过 1080p 的降到 1080p |
| 10bit 视频，但解码器不支持 10bit（H.264 Hi10P 一律视为不支持） | 重新编码，超过 1080p 的降到 1080p |
| 杜比视界 Profile 5，且设备没有杜比视界解码器 | 重新编码 |
| 音频编码设备和 FFmpeg 都不支持 | 只转音频 |
| HDR 片源，但设置里关闭了“电视支持 HDR” | 转成 SDR，降到 1080p |
| 字幕本机显示不了，且开启了“允许服务器烧录字幕”（默认关闭） | 重新编码并烧录字幕 |

### 播放过程中自动改用转码

以下两种情况会从当前位置改用转码继续播放，每次起播最多切换一次：

- **直接播放出错**：
  - 如果是视频解码失败（设备声称支持但实际解不了），重新编码视频。
  - 如果是封装或解析问题，只换封装。
- **文件不能跳转**（比如没有索引的 MKV）：续播或快进时，改由服务器从目标位置开始。

网络错误不会触发转码，播放器会先重连重试。

### 转码输出

- 格式是 HLS + TS 分片，视频编码为 H.264 或 HEVC；转成 SDR 时只用 H.264。
- **Plex**：EAC3（最多 7.1）、AC3（5.1）、DTS 原样保留；TrueHD 放不进 TS，服务器会转成 EAC3。
- **Jellyfin / Emby**：AAC、AC3、EAC3、MP3、Opus、FLAC 原样保留；DTS 由服务器转换。
- 转码后的流里没有内封字幕：
  - 外挂文本字幕（SRT、ASS、VTT）仍由本机显示。
  - 图形字幕（PGS 等）和内封字幕只能由服务器烧录。视频本来就要重新编码时，即使没开烧录开关，也会自动烧录。

## HDR

- **片源识别**：
  - Plex：识别 HDR10、HLG、杜比视界。HDR10+ 会当作 HDR10。
  - Jellyfin / Emby：识别 HDR10、HDR10+、HLG、杜比视界。
- **是否输出 HDR 以设置里的“电视支持 HDR”为准**，默认开启。系统检测结果不可靠（不少盒子总是报告支持，或者什么都不报告），只在“播放信息”里作为参考显示。
- **开启时**：HDR 片源直接播放，由盒子和电视处理 HDR 信号。
- **关闭时**：所有 HDR 片源（包括 HLG 和杜比视界）都由服务器转成 1080p SDR H.264，避免在不支持 HDR 的电视上画面发灰。前提是服务器上开启了 HDR 色调映射，否则颜色仍然不对。
- 播放器本身不做色调映射。

## 杜比视界

| Profile | 设备有杜比视界解码器 | 设备没有杜比视界解码器 |
|---|---|---|
| **5**（没有 HDR10 兼容层） | 直接播放 | 起播前就让服务器转码，否则颜色会完全错误 |
| **8**（8.1 / 8.4） | 直接播放 | 用 HEVC 解码器播放 HDR10 / HLG 基础层 |
| **7**（UHD 蓝光双层） | 直接播放；如果解码器卡住，自动改为只播基础层（见下文） | 用 HEVC 解码器播放 HDR10 基础层 |

**杜比视界解码器卡住时**：很多盒子声称支持 Profile 7，实际却不出画面（比如极米会一直转圈）。如果数据已经缓冲够了，等待 8 秒仍没有第一帧，播放器就认为解码器卡住了，然后：

1. 记住这台设备的这个 Profile。
2. 重新打开播放页，用 HEVC 解码器只播放 HDR10 基础层。

以后再播放同一 Profile 的片源，会直接走基础层。

只播基础层时，画面是 HDR10，没有杜比视界的动态元数据。基础层能否正常显示，仍然取决于上文 HDR 一节的设置。

## 音频

- **默认关闭直通。** 所有音频解码成 PCM，多声道会下混成立体声：中置和环绕声道按 -3dB 混入左右声道，LFE 丢弃。这样可以倍速播放，也兼容投影仪和电视自带的喇叭。代价是杜比全景声（Atmos）信息会丢失。
- **开启“音频直通”**（接功放时使用）：AC3、EAC3（包括全景声 EAC3-JOC）、DTS、TrueHD 等以原始码流交给功放解码。能直通哪些格式，取决于系统报告的 HDMI 能力。直通的音轨不能倍速，会固定 1x 播放。

## 字幕

- 直接播放时：
  - SRT、ASS / SSA、WebVTT、PGS、VobSub、DVB 字幕都由本机渲染。
  - ASS / SSA 用 libass 渲染，保留字体、位置和特效。
- 转码时的规则见上文“转码输出”。

## 排查

- 播放时在菜单里打开“播放信息”，可以看到播放方式、转码原因、视频和音频解码器、是否直通，以及 HDR 状态。
- debug 包会把起播决策写进日志（`plan ... -> 播放方式 reasons=...`），用 `adb logcat -s LumyPlayer` 查看。关闭了 logcat 的设备（如极米）上，debug 包还会把日志写到文件里：

  ```bash
  adb shell run-as com.hesier.lumy.debug cat files/debug.log
  ```
